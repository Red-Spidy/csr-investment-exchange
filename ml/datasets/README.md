# Synthetic CSR datasets

Generated by `make datasets` (code in `ml/synth/`, seed 7). The same seed always
produces byte-identical files, so anyone on the team can regenerate them.

| File | Rows | One row per | Used to train |
|---|---:|---|---|
| `ngos.csv` | 500 | NGO | Features for the impact model |
| `projects.csv` | 2,000 | Project proposal and its outcome | XGBoost (impact); labels for BERT |
| `spending.csv` | 2,416 | NGO per financial year, FY19-20 to FY23-24 | Isolation Forest (fraud) |
| `proposals.jsonl` | 1,300 | Written proposal for one project | BERT (SDGs, metric, fields) |

The CSVs come from `make datasets`. The proposal text comes from `make proposals`
(code in `ml/textgen/`), which needs API keys and is not byte-reproducible --
see [Proposal text](#proposal-text) below.

## How the world works

Every NGO has two **hidden traits** that drive everything but are never model
features:

- `hidden_capacity` — how well it delivers projects, Beta(4, 3)
- `hidden_is_fraudulent` — 6% of NGOs misuse funds

Models only see the noisy *consequences* of those traits:

| Hidden trait | What leaks out, and where |
|---|---|
| Capacity | Past delivery rate (`ngos.past_delivery_rate`, noisier for NGOs with few past projects); vaguer proposals from weaker NGOs (`projects.states_*`) |
| Fraud | Padded budgets — higher cost per beneficiary for the sector; heavier administration budget line; 1–3 spending years that break the NGO's own pattern on 1–4 markers |

A project's **outcome** (`delivered_fraction`, the share of the claimed
improvement actually delivered) depends on capacity, whether the budget is
realistic for the number of beneficiaries, how ambitious the claim is, the
sector, fraud, and luck. `achieved_delta` is the same outcome in the
proposal's own units, e.g. +5.2 percentage points of attendance.

Honest NGOs also have **legitimate spikes** (4% of their years): a one-off big
grant that inflates spend and pace but none of the fraud markers. There are
more of these than fraud years, so the fraud model faces realistic false
alarms.

## Column guide

- **`hidden_*`** columns are never features. They exist to evaluate models and
  to train an *oracle* that shows the best score achievable.
- **Labels:** `delivered_fraction` / `achieved_delta` (impact),
  `is_anomalous_truth` (fraud), `sdgs` (BERT).
- **`split`** is assigned per NGO (70 / 15 / 15, stratified on fraud), and every
  project and spending row inherits its NGO's split. No NGO appears in two
  splits, so a model cannot score well by memorising an NGO.
- `activities`, `sdgs` and `budget_lines` are JSON. SDGs follow from the
  activities a project describes — "midday meal support" serves SDGs 2 and 4.

## Assumptions (not sourced)

- 6% of NGOs are fraudulent. No public figure exists.
- Cost per beneficiary norms (education ₹450, healthcare ₹700, water ₹70,
  environment ₹600, livelihood ₹2,500) mirror the demo scenario in
  `db/seed.sql`, so the trained models score demo projects in a familiar range.
- Twelve states, sampled uniformly. District names are real.
- The outcome coefficients and fraud shift sizes in `ml/synth/world.py` are
  design choices, tuned so the outcome distribution matches IEG.

## Quick signal check

A throwaway check run while building the data, not the final models:

| Task | Baseline | Observable features | Oracle (hidden traits) |
|---|---|---|---|
| Outcome, test split (unseen NGOs) | R² 0.00, MAE 0.185 | R² 0.21, MAE 0.161 | R² 0.33, MAE 0.148 |
| Fraud, grouped 5-fold CV, raw Isolation Forest | avg precision 0.025 (random) | ROC-AUC 0.886, avg precision 0.28 | — |

No model can reach R² 1: luck and local conditions are part of the outcome, as
in reality.

## Limitations

- **The causal structure is ours.** Models trained here learn our stated
  assumptions. Results show the methods work under those assumptions, not
  real-world accuracy.
- The test split holds only ~5 fraud NGOs. Evaluate the fraud model with
  grouped cross-validation over all NGOs (61 fraud years), not the test split alone.
- Five sectors only. SDGs 10, 16 and 17 never appear.

## Proposal text

`proposals.jsonl` holds one LLM-written proposal per project: 1,300 so far,
all by Gemini 3.5 Flash-Lite. About 700 more are planned from a second model
(Groq), so BERT can be tested on a writing style it never trained on.

**How a proposal is made.** Each project's facts -- NGO, district, activities,
beneficiaries, baseline and target, duration, budget -- go to the LLM on a fact
sheet whose labels, order and wording are varied per project (activity
descriptions, metric phrasing and budget item names all have alternatives),
with one of 8 writing styles and 4 target lengths. The LLM writes only the
prose; every label is known before the text exists.

**Every proposal is checked** (`ml/textgen/checker.py`) and regenerated, up to
three tries, unless it:

- states every fact it was given, with the exact number (lakh, crore and Indian
  digit grouping understood);
- describes every activity -- the SDG labels follow from the activities;
- leaves out what it was told to leave out;
- invents no number (citations of Section 135 of the Companies Act, 2013 are
  allowed; 166 proposals make one);
- does not name SDGs outright, so BERT must infer them from what the project does.

**Deliberate gaps teach abstention.** 282 proposals give no baseline, 210 no
beneficiary count and 397 no budget breakdown. A reader that fills those in is
hallucinating, and the evaluation counts it.

| Column | Meaning |
|---|---|
| `project_id` | Joins to `projects.csv`, which holds the SDGs, metric and true values |
| `text` | The proposal |
| `spans` | Character positions of each stated fact, the field extractor's labels |
| `provider`, `model` | Which LLM wrote it |
| `style`, `length_words` | What it was asked for |
| `prompt_version` | `p2` (305 proposals) or `p3` (995): p3 adds varied metric and budget wording and allows legal citations |

Measured on the corpus: activity names copied word for word in 10.7% of
activities (96% before the fact sheet was varied); median length 142 words
(54-330).

**Limitations.** One LLM so far, so one model's habits. Invented details written
in words ("twelve-year-old Meena") are not checked; only numbers are. Because
the checker requires each activity's keywords, a keyword baseline is flattered
on this corpus -- compare readers on text the checker never shaped.
