# Impact model: measured findings

Dataset: IEG World Bank Project Performance Ratings (Kaggle), 12,932 rows.
After dropping `Not Rated` / `Not Available` / `Not Applicable` (180 rows):
**12,752 usable projects**.

Target: `IEG_Outcome`, a 6-point ordinal rating, mapped to `impact_norm` in
[0,1] to satisfy `impact_predictions.impact_norm CHECK (BETWEEN 0 AND 1)`.

| Rating | n | impact_norm |
|---|---:|---:|
| Highly Unsatisfactory | 178 | 0.0 |
| Unsatisfactory | 2127 | 0.2 |
| Moderately Unsatisfactory | 1108 | 0.4 |
| Moderately Satisfactory | 2853 | 0.6 |
| Satisfactory | 6081 | 0.8 |
| Highly Satisfactory | 405 | 1.0 |

Target mean 0.616, SD 0.243. The distribution is skewed: `Satisfactory` alone
is 48% of all rated projects.

## Finding 1: outcome is not predictable from proposal-time features

Features available when a CSR proposal is scored are sector, budget and
duration. Nothing else in this dataset transfers (see Finding 3).

Evaluation uses a **temporal split on Exit FY** (cut at 2011, 10,414 train /
2,338 test). A random split leaks: projects from one era share macro conditions
and appraisal practice, so random holdout flatters the model.

| Setup | Model R² | Constant-baseline R² |
|---|---:|---:|
| Temporal split | **-0.007** | -0.030 |
| Random split | **+0.037** | 0.000 |
| Random, Exit FY >= 2000 | **+0.027** | 0.000 |

**Sector, budget and duration explain roughly 3% of outcome variance.**

Sector base rates span a narrow band against a target SD of 0.243:

| Sector | mean | n |
|---|---:|---:|
| Public Sector Governance | 0.566 | 665 |
| Health, Nutrition and Population | 0.577 | 626 |
| Agriculture and Rural Development | 0.586 | 2675 |
| Water | 0.593 | 661 |
| Education | 0.651 | 1102 |
| Social Protection | 0.654 | 411 |
| Transport | 0.671 | 1421 |

This is a property of the problem, not a tuning failure. Project success
depends on execution, governance and local conditions -- none of which are
visible in a proposal.

## Finding 2: no configuration beats predicting the mean

Constant baseline MAE: **0.1469**. Point models use `reg:absoluteerror`, which
minimises MAE directly, so this is the fairest possible comparison.

| 3 | 400 | 0.1627 |

| 4 | 150 | 0.1620 |

**All nine lose to the constant.** Interval models reach 0.93 coverage against

## Finding 3: two traps in this dataset

**Leakage.** The `IEG_*` performance columns are assigned by the *same
evaluation* that assigns `IEG_Outcome`, so they cannot exist when a proposal is
scored. Including `IEG_OverallBankPerf`, `IEG_ICRQuality`,
`IEG_BankQualityAtEntry` and `IEG_OverallBorrPerf` lifts R² from **0.03 to
0.499**. `ERR at Completion` is leakage for the same reason. That number is
reportable only as a demonstration of what not to do.

**Raw fiscal years destroy interval calibration.** Feeding `Approval FY` and
`Exit FY` as features under a temporal split gives every test row an unseen
year, so trees split on year and funnel the test set into one extrapolated
leaf. Measured effect: coverage fell from 0.884 to **0.679**. A miscalibrated
interval is worse than no interval, because a reviewer trusts it.

## What shipped

A **sector base-rate model with empirical quantiles**, as
`db/migrations/006_impact_baserates.sql`. It lives in SQL rather than Python so
the architecture's rule still holds: the models produce evidence, SQL decides.

`impact_sector_baserates`, generated by `ml/impact/build_baserates.py`:

|---|---:|---:|---:|---:|---:|
| _global | 12752 | 0.6156 | 0.20 | 0.80 | 0.7324 |
| education | 1102 | 0.6510 | 0.20 | 0.80 | 0.7895 |
| environment | 471 | 0.5992 | 0.20 | 0.80 | 0.7176 |

`mean_outcome` is the historical **fraction of plan delivered**: 0.65 reads as
"education projects delivered about 65% of what they promised".

### Why q10/q90 are identical across sectors

This looks like a bug and is not. The IEG scale has six discrete levels and 48%
of all rated projects sit on one of them (`Satisfactory` = 0.8), so the 10th and
90th percentiles land on the same two levels in every sector. It is also the
headline finding restated: sector moves the *mean* by a few points while
project-level spread dominates.

`p_satisfactory` -- P(outcome >= Moderately Satisfactory) -- is reported
because it *does* discriminate: 0.671 for healthcare against 0.790 for
education, a 12-point spread versus the mean's 7.

### How a prediction is produced

`fn_predict_impact(project_id)` scales the claim the NLP module extracted by
the sector base rate, so the forecast lands in the proposal's own units:

> Project 1 claims attendance 61 -> 69, a delta of +8 points. Education
> delivers ~0.651 of plan, so predict **+5.21 points, 80% CI [1.6, 6.4]**.

Two branches, both tested:

- **target metric present** -- scale the delta. A claimed *reduction* makes the
  delta negative and inverts the interval, so bounds are ordered by value, not
  by which quantile produced them, or the `ci_ordered` CHECK rejects the row.
- **target metric absent** -- the proposal stated nothing measurable, so report
  the base rate as itself (`outcome_score` / `normalised_0_1`) rather than
  invent a denominator. This is the NLP module's abstention design paying off
  downstream.

Verified by `db/tests/07_impact_predictions.sql`: six assertions against
hand-computed values, covering positive delta, negative delta, absent target,
idempotent re-scoring, unmapped-sector fallback, and table well-formedness.

A GPU is irrelevant here: the whole model is a `GROUP BY`, and the ceiling is
set by the data rather than by training time.
